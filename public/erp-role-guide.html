🧩 What is ASDairy ERP?

ASDairy ERP is a full-featured web-based Enterprise Resource Planning system built for dairy farm businesses. It combines:

  • Dairy Farm Management — Animals, milk production, breeding, health records, feed plans
  • HR & People Management — Employees, attendance, leaves, salaries, shifts, timesheets
  • Financial Control — Transactions, expenses, wallets, fraud detection, audit logs
  • Inventory Control — Items, categories, stock movements, auto-deduction
  • CRM & Sales — Contacts, customers, franchise network, procurement, vendors, sales orders
  • Work Tracking — Tasks, projects, work reports, team management
  • Compliance & Maintenance — Documents, machine maintenance, compliance records
  • Role-based Access Control — Granular per-module permissions per role
🛠 Tech Stack
  • Framework: Laravel 12 (PHP 8.3+)
  • Frontend: Blade templates + Bootstrap 5 + Bootstrap Icons
  • Database: MySQL (XAMPP locally, production server)
  • Auth: Laravel built-in + 2FA (TOTP/email OTP)
  • Queue: Laravel Queue (database driver) for background jobs
  • Scheduler: Laravel Scheduler via cron (Linux) / Task Scheduler (Windows)
  • Session: File-based sessions
  • Cache: File/database cache (5-min permission cache)
  • Storage: Local disk (documents, photos, reports)
  • Notifications: In-app (AppNotification model) + email
  • Deployment: Apache (XAMPP dev) / Linux production server

🔑 Access Control System
ASDairy uses a two-layer permission system: Role-based middleware + per-module Service Permissions stored in the database.
  • Layer 1 — Role Middleware: middleware('role:super_admin') — blocks entire route groups by role name
  • Layer 2 — Service Permissions: middleware('service:wallets') — checks ServicePermission model for the user's role + service key
  • Sidebar Visibility: PHP flags computed in app.blade.php — sections hidden when role has no access to any item in that section
  • Cache: Permission lookups are cached for 5 minutes per key (svc_perm_{key})
  • Super Admin: Bypasses all permission checks — always returns true
// ServicePermission::canAccess()
Cache::remember("svc_perm_{$key}_{$user->id}", 300,
  fn() => DB::table('service_permissions')
    ->where('role', $user->role)
    ->where('service_key', $key)
    ->where('is_enabled', 1)
    ->exists()
);
🔐 Authentication & Security
Login Flow
1. POST /login → Auth\LoginController@login
2. Validate credentials (email + password)
3. Check user status (active/suspended/blacklisted)
4. If 2FA enabled → redirect to /2fa page
5. Verify OTP/TOTP code
6. Create session + LoginHistory record
7. Redirect to role dashboard
Blacklist check: Users in Blacklist table are denied login regardless of credentials.
Security Features
  • 2FA: Time-based OTP or email verification code on every login
  • Login History: Every login recorded in login_histories (IP, user-agent, timestamp)
  • Activity Tracking: TrackActivity middleware logs page visits to activity_logs
  • Audit Log: CRUD operations recorded in audit_logs
  • Fraud Detection: FraudDetectionService checks transactions against rules in real-time
  • Fraud Alerts: Suspicious transactions trigger FraudAlert records + admin notifications
  • User Blacklist: Admin can blacklist users, blocking future logins
  • Password Change: All users can change their password via /change-password
  • Check Status: CheckUserStatus middleware blocks suspended accounts on every request

🐄 Dairy Farm Module
🐄 Animals
  • Model: Animal — tag_no, name, animal_id, rfid, animal_type, breed_id, group_id, dob, source, status, notes
  • Animal Types: Cow, Buffalo, Calf, Bull, Heifer (configurable)
  • Grouping: Assigned to AnimalGroup (used in feed plans)
  • Breeds: Breed model with name + description
  • Photos: Multiple photos per animal via AnimalPhoto
  • Actions: Logged events (vaccination, treatment, etc.) via AnimalAction + ActionType
  • Sources: Born on farm, purchased, transferred — tracked with source fields
  • RFID: Optional RFID tag field for physical tagging
Controller: Admin\AnimalController — full CRUD + photo upload + action log
🥛 Milk Production
  • Model: MilkEntry — animal_id, date, session (morning/evening), quantity_litres, clr_value, entry_type, shed
  • Sessions: Morning and Evening entries per animal per day
  • CLR Value: Corrected Lactation Record — milk quality metric
  • Entry Types: Individual animal entry or shed-level batch entry
  • Reports: Daily/monthly production summaries, per-animal trends
  • Controller: Admin\MilkController
Milk data feeds into Farm Records for overall dairy performance tracking.
🧬 Breeding
  • Model: BreedingRecord — animal_id, date, method (AI/natural), bull_breed, expected_calving, status (pregnant/not_pregnant/calved/aborted), certificate_path
  • Status Tracking: Tracks pregnancy status and outcome
  • Documents: Certificate file upload per record
  • Controller: Admin\BreedingController
🏥 Health Records
  • Model: HealthRecord — animal_id, date, type (vaccination/treatment/checkup/deworming), description, vet_name, cost, report_path, next_due
  • Report Upload: PDF/image reports per health event
  • Next Due: Tracks when next treatment/vaccination is due
  • Alerts: SendDairyAlerts cron sends reminders for upcoming due dates
  • Controller: Admin\HealthController
🌾 Feed Plans & Auto-Deduction
  • Models: FeedPlan, AnimalGroup, InventoryItem
  • Feed Plan: Defines daily quantity of an inventory item per animal in a group
  • Service: FeedDeductionService::runDeduction()
  • Logic: AnimalGroup × active FeedPlans → daily need per item → check stock → create StockMovement (type=out)
  • Duplicate Guard: Skips items already deducted today (checks existing StockMovement)
  • Partial Stock: Deducts available amount if stock < required, flags as partial
  • Cron: dairy:feed-deduction runs daily at 06:00
  • Manual Run: "Run Daily Deduction" button in Feed Calculator UI
  • History: /admin/feed/deductions — filterable log grouped by date
FeedDeductionService::runDeduction()
  └─ foreach AnimalGroup
      └─ foreach FeedPlan (item + qty/animal/day)
          ├─ dailyNeed = qty × group.animal_count
          ├─ check StockMovement for today (skip if exists)
          ├─ deductQty = min(dailyNeed, available_stock)
          └─ create StockMovement (type=out, source_purpose=Feed)

⚙️ Business Services
🌾 FeedDeductionService
  • runDeduction(recordedBy): Main deduction loop — processes all active groups and feed plans, creates StockMovement records
  • getTodayDeductionStatus(): Returns per-feed-item deduction status for today (used in calculator UI)
  • Duplicate Guard: Checks for existing StockMovement with same item + today + Feed source
  • Returns: ['deducted', 'skipped', 'not_found', 'no_stock'] arrays
🧮 FeedCalculationService
  • Purpose: Calculates required feed quantities based on animal groups and feed plans (read-only calculation, no DB writes)
  • Used in: Feed Calculator UI to show daily requirements before deduction
  • Considers: Group animal count × qty_per_animal_per_day = daily need per item
🔍 FraudDetectionService
  • Purpose: Evaluates transactions against configured FraudRule records
  • Rule Types: Velocity checks (too many transactions), amount threshold, unusual hours, duplicate detection
  • On Match: Creates FraudAlert, optionally blocks transaction, notifies admins via NotificationService
  • Called By: TransactionController on every new transaction + cron jobs
📊 DashboardService
  • Purpose: Aggregates stats for admin dashboard — counts, totals, recent activity
  • Provides: Total employees, animals, milk today, pending tasks, open fraud alerts, recent transactions
  • Used in: Admin\DashboardController@index
⏰ AttendanceService
  • Purpose: Handles attendance mark/unmark logic, late detection, half-day rules
  • Considers: Employee's shift timings, holiday calendar
  • Used in: Admin\AttendanceController and automated reminder cron
🔔 NotificationService
  • Purpose: Creates AppNotification records and optionally sends emails
  • Used by: Fraud alerts, leave approvals, task assignments, dairy alerts, attendance reminders
  • In-App: Notifications appear in topbar bell icon with unread count
  • History: /notifications/history — paginated notification log with "mark all read" button
🏭 ASDairyErpService
  • Purpose: Top-level ERP service for cross-module operations and system-wide utilities
  • Provides: System settings lookup, global configuration, shared utility methods used across multiple modules

🛡 Roles & Permissions
10 System Roles
super_adminUnrestricted access to everything. Bypasses all permission checks. Can add/freeze wallets, manage all users.
adminFull administrative access except super-admin-only actions. Manages users, roles, permissions.
managerOperational management — approves leaves, oversees tasks, manages team productivity.
hr_managerHR-focused access — employees, attendance, salaries, leaves, shifts, departments.
finance_managerFinance operations — transactions, expenses, wallets view, fraud alert resolution.
auditorRead-only financial oversight — transactions, wallets, audit logs, fraud alerts view.
farm_managerFull dairy farm module — animals, milk, breeding, health, feed plans, inventory.
crm_agentCRM & sales access — contacts, customers, franchise, sales orders, vendors.
employeeSelf-service portal — own attendance, tasks assigned, work reports, timesheet.
viewerRead-only dashboard access. Can view reports and summaries, cannot modify data.
How Role Assignment Works
  • Each User has a role varchar field (e.g. "admin", "hr_manager")
  • Roles are defined in the roles table with display_name and description
  • Super Admin assigns roles via Admin\UserController or Admin\RoleController
  • The CheckRole middleware reads auth()->user()->role and compares to required role(s)
  • Service permissions are assigned per role via Admin\ServicePermissionController
  • Changing a role's permissions clears the 5-min cache immediately for fresh enforcement
  • Users land on role-dashboard.blade.php showing their accessible modules with gradient cards
Role Dashboard: After login, each user is redirected to /admin/role-dashboard which shows only the modules their role can access, with animated stat cards and module navigation cards.

🌾 Feed Auto-Deduction Flow
Cron 06:00 → dairy:feed-deduction
FeedDeductionService::runDeduction(recordedBy=1)
Loop: foreach AnimalGroup (active)
Loop: foreach FeedPlan for group (is_active=true)
dailyNeed = plan.qty_per_animal × group.animal_count
Check: StockMovement exists today for this item? → skip
Check: InventoryItem.current_stock > 0
deductQty = min(dailyNeed, current_stock)
Create StockMovement (type=out, source_purpose=Feed)
Update InventoryItem.current_stock -= deductQty
Return summary: deducted / skipped / not_found / no_stock
🔍 Transaction Fraud Check Flow
User submits new Transaction
TransactionController@store validates input
Transaction record created (status=pending)
FraudDetectionService::check($transaction)
Load active FraudRules from DB
Evaluate each rule (velocity, amount, time, duplicates)
Rule matched? → Create FraudAlert (severity: low/med/high)
Action=block? → Transaction status=blocked
NotificationService → alert Finance Manager + Admin
TransactionLog records status change
Response returned to user (success or blocked)
🔑 Permission Check Flow
Request hits route with middleware('service:wallets')
CheckServicePermission middleware fires
Get authenticated user's role
isSuperAdmin()? → pass through immediately
Cache::get("svc_perm_wallets_{user_id}")
Cache miss → query service_permissions table
WHERE role=? AND service_key='wallets' AND is_enabled=1
Store result in cache for 300s
is_enabled=true → continue to controller
is_enabled=false → abort(403)
🥛 Milk Entry Flow
Farm Manager opens Milk Entry page
Select Animal + Session (morning/evening)
Enter quantity_litres + CLR value
Select entry_type (individual animal / shed batch)
MilkController@store saves MilkEntry
FarmRecord for today updated with aggregate totals
Dashboard stats refresh (total milk today)
Monthly cron aggregates into GenerateMonthlyReports
👤 Login & 2FA Flow
POST /login → LoginController@login
Validate email + password
Check Blacklist table → deny if found
Auth::attempt() → verify credentials
Check user.status (active/suspended) → deny if suspended
2FA enabled? → generate OTP → redirect /2fa
POST /2fa → verifyTwoFactor → check OTP validity
OTP valid → complete login → create session
Create LoginHistory record (IP, user-agent, timestamp)
Redirect → /admin/role-dashboard
📋 Task Assignment Flow
Manager/Admin creates Task (title, assignee, due_date, priority)
TaskController@store saves task with status=pending
NotificationService creates AppNotification for assignee
Assignee sees task in their Employee Portal
Assignee updates status (in_progress / completed)
TaskComment added for discussion/updates
Recurring Task? → CreateRecurringTasks cron creates next instance
Timesheet entry linked to task for hour tracking
